Encryption Study Guide: DES, AES & RC4

1. Data Encryption Standard (DES)

What is DES? (Simple Explanation)

Think of DES as a machine that takes 8 characters of text and a password (key), then scrambles those characters 16 times in a row. Each scrambling round follows the same pattern but uses a different part of the password.

Key Facts:

  • Block size: 64 bits (8 characters)
  • Key size: 56 bits (+ 8 parity bits)
  • Structure: Feistel network with 16 rounds
  • Status: Considered insecure today (key too small)

2. Advanced Encryption Standard (AES)

What is AES? (Simple Explanation)

AES treats data as a 4×4 grid of bytes (like a small spreadsheet). It performs four operations on this grid multiple times: substitute bytes (using a lookup table), shift rows (move bytes left), mix columns (math operation), and add round key (mix with key). This process repeats 10-14 times.

Key Facts:

  • Block size: 128 bits (16 bytes)
  • Key sizes: 128, 192, or 256 bits
  • Rounds: 10 (128-bit key), 12 (192-bit), 14 (256-bit)
  • Status: Current standard, considered secure

3. RC4 Stream Cipher

What is RC4? (Simple Explanation)

Unlike DES and AES which encrypt blocks of data, RC4 creates a stream of random-looking bytes that are combined (XORed) with your message one byte at a time. It's like having a one-time pad that's generated on the fly.

Key Facts:

  • Type: Stream cipher (not block cipher)
  • Key size: Variable (typically 40-256 bits)
  • State: 256-byte array (S-box)
  • Status: Not recommended for new applications

Exam Practice Questions

Question 1: Compare and contrast DES and AES

Explain the key differences between DES and AES in terms of structure, security, and performance. Why was AES chosen to replace DES?

How to Answer:

  1. Start with a comparison table:
    • DES: 64-bit block, 56-bit key, 16 rounds, Feistel network
    • AES: 128-bit block, 128/192/256-bit key, 10/12/14 rounds, Substitution-Permutation Network
  2. Explain security differences:
    • DES: Vulnerable to brute force (2^56 keys can be searched)
    • AES: Resistant to known attacks (2^128 keys minimum)
  3. Mention performance: AES is faster on modern hardware and has dedicated CPU instructions
  4. Conclude: AES replaced DES because of larger key size, better security margin, and improved performance

Question 2: Explain the AES round transformations

Describe in detail the four transformations that occur in each round of AES encryption. What is the purpose of each transformation?

How to Answer:

  1. SubBytes:
    • What it does: Substitutes each byte using a fixed S-box lookup table
    • Purpose: Provides non-linearity, confusion
    • Example: Byte value 0x53 might be replaced with 0xED
  2. ShiftRows:
    • What it does: First row stays as is, second row shifts 1 byte left, third row shifts 2 bytes left, fourth row shifts 3 bytes left
    • Purpose: Diffusion, spreading changes across columns
    • Example: [a,b,c,d] becomes [a,b,c,d], [b,c,d,a], [c,d,a,b], [d,a,b,c]
  3. MixColumns:
    • What it does: Matrix multiplication in Galois Field GF(2^8)
    • Purpose: Diffusion, mixing data within columns
    • Example: Each column is multiplied by a fixed matrix
  4. AddRoundKey:
    • What it does: XOR state with round key derived from main key
    • Purpose: Introducing key material, creating dependency on key
    • Example: Byte 0xA3 XOR key byte 0x5F = 0xFC

Question 3: Describe RC4's weaknesses and why it's no longer recommended

Explain the specific weaknesses in RC4 that led to its deprecation. Provide examples of attacks or vulnerabilities.

How to Answer:

  1. Biased output:
    • First few bytes of keystream are statistically biased
    • Some byte values appear more frequently than others
    • Example: Second byte is zero with probability 1/128 (should be 1/256)
  2. Related key vulnerabilities:
    • Weak key scheduling algorithm
    • Similar keys can produce related outputs
    • Example: Flipping a bit in the key causes predictable changes
  3. Real-world attacks:
    • WEP (wireless encryption) was broken due to RC4 weaknesses
    • BEAST and other attacks against TLS/SSL using RC4
    • Example: FMS attack exploited biases to recover WEP keys

Question 4: Explain the DES Feistel Structure and Its Advantages

Describe the Feistel structure used in DES, including how data flows through the rounds. Explain the advantages of this structure and why it was significant in cryptographic design.

How to Answer:

  1. Start with a diagram:

    Draw a simple Feistel network diagram showing:

            |             |

            |      |

            |      |

          Right32       New Left32
            |             |
            +------+------+
                   |
              Next Round

    Label clearly: input block, left/right halves, F-function, round key, and XOR operation

  2. Describe the process in detail:
    • Input block is split into two 32-bit halves (L₀, R₀)
    • For each round i (1 to 16):
      • Li = Ri-1
      • Ri = Li-1 ⊕ F(Ri-1, Ki)
      • Where Ki is the round key and F is the round function
    • After final round, perform a 32-bit swap: (R16, L16)
    • Apply final permutation (IP-1)
  3. Explain the F-function in detail:
    • Expansion: 32-bit Ri-1 is expanded to 48 bits
    • Key mixing: XOR with 48-bit round key Ki
    • Substitution: Result passes through 8 S-boxes, each taking 6 bits and outputting 4 bits
    • Permutation: 32-bit output is rearranged according to P-box
  4. Discuss advantages of Feistel structure:
    • Encryption and decryption are structurally identical (just reverse key schedule)
    • Same hardware/software can be used for both operations
    • Self-inverting structure simplifies implementation
    • Security doesn't depend on the reversibility of the F-function
    • Allows for complex non-linear operations without needing to invert them
  5. Historical significance:
    • First widely-used block cipher design pattern
    • Influenced many subsequent ciphers (BLOWFISH, TWOFISH, etc.)
    • Demonstrated how to achieve Shannon's principles of confusion and diffusion

Question 5: Analyze the Security Implications of Key Size in Symmetric Encryption

Compare the security provided by different key sizes (56-bit DES, 128-bit AES, 256-bit AES) against various attack vectors. Include quantitative analysis of brute force resistance and discuss when larger keys are necessary.

How to Answer:

  1. Create a comparison table:
    Algorithm Key Size Possible Keys Brute Force Resistance
    DES 56 bits 256 ≈ 7.2 × 1016 Breakable in hours with specialized hardware
    AES-128 128 bits 2128 ≈ 3.4 × 1038 Infeasible with current technology
    AES-256 256 bits 2256 ≈ 1.2 × 1077 Beyond foreseeable future technology
  2. Quantitative analysis of brute force attacks:
    • Calculate and show work for time required to brute force each key size:
    • For DES (56-bit):
      • If testing 1 billion keys/second: 256 ÷ 109 ÷ 3600 ÷ 24 ≈ 833 days
      • With specialized hardware (EFF DES Cracker, 1998): ~56 hours
      • With modern ASIC/FPGA arrays: minutes to hours
    • For AES-128:
      • If testing 1 billion keys/second: 2128 ÷ 109 ÷ 3600 ÷ 24 ÷ 365 ≈ 1022 years
      • Even with a billion machines each testing a billion keys/second: 1013 years
  3. Discuss quantum computing threat:
    • Grover's algorithm reduces effective key strength by half
    • 56-bit DES → effectively 28-bit (trivially breakable)
    • 128-bit AES → effectively 64-bit (potentially vulnerable)
    • 256-bit AES → effectively 128-bit (still secure)
    • Draw a simple diagram showing how quantum computing affects security margins:

  4. Practical considerations:
    • Performance impact: Larger keys require more processing power and memory
    • AES-256 is ~40% slower than AES-128 on many platforms
    • Key storage and transmission overhead increases with key size
    • Key management complexity increases with key size
  5. When larger keys are necessary:
    • Long-term data protection (information that must remain secure for decades)
    • High-value targets (financial, military, government systems)
    • Quantum-resistant applications
    • Compliance requirements (e.g., Suite B cryptography requires AES-256 for TOP SECRET)
  6. Conclude with balanced recommendation:
    • DES (56-bit): Obsolete and should never be used in new applications
    • AES-128: Sufficient for most current commercial applications
    • AES-256: Recommended for high-security applications and future-proofing
    • Key size is only one factor; implementation quality and overall system security are equally important
